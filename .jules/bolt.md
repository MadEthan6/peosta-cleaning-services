## 2024-05-15 - React Component Definition and Memoization Anti-Patterns
**Learning:** Defining functional components inside other functional components (e.g., `JobCard` inside `ClientHistory`) is a performance anti-pattern. It triggers full unmounting and remounting of the nested component on every render of the parent component, defeating React's reconciliation process. Additionally, computing arrays directly in the render method based on state (like `jobs.filter(...)`) causes expensive redundant recalculations during unrelated state updates (like merely selecting an item).
**Action:** Extract nested component definitions outside their parent components. Wrap them in `React.memo` and pass required data explicitly via props. When dealing with selection state, pass derived primitive boolean props (like `isSelected={selected?.id === job.id}`) instead of global objects/IDs to maximize memoization benefits. Combine and memoize chained array operations using `useMemo` so they only recalculate when their specific dependencies change.
